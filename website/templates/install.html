What changed in this alpha

  • Ninja-Update verifies and tests new versions separately, then lets you restart or revert while preserving your authored integration and application data.
  • Cleared text stays empty when you submit a viewer command.
  • Pause and Stop remain effective while final evidence is collected.
  • Visible typing and cursor movement make guarded actions easier to follow.
  • CLI shutdown preserves the final report and retries failed owned cleanup.

Stopping cannot undo a request already sent. Execution, application outcome and persistence evidence remain separate.

1. Download and verify

Save the ZIP and its SHA256SUMS file in the same new folder. Before extracting or running the kit, compare the archive’s SHA-256 with the value below. The checksum file covers the ZIP only.

EXPECTED ZIP SHA-256{{ZIP_SHA256}}

From that folder, check the checksum and then extract the archive: 

shasum -a 256 -c SHA256SUMS && \
  unzip daedlo-{{VERSION}}.zip

Continue only when the check reports OK. This checks download integrity against the published digest; it does not verify your application’s behavior. Use a local SHA-256 tool if your system does not provide shasum.

2. Verify and install the tools

In your terminal, enter the newly extracted folder:

cd daedlo-{{VERSION}}

Run this complete block. It is the same block verified from the kit’s START_HERE.md: check the tools archive before running it, install the portable tools, then verify the runtime and engine bundle.

macOS tools installation commands 
(
  set -eu
  driver_kit="$(pwd -P)"
  node --input-type=module - "$driver_kit/tools/browser-driver-tools-{{VERSION}}.tgz" <<'NODE'
import { readFileSync } from 'node:fs';
import { createHash } from 'node:crypto';
const digest = createHash('sha256').update(readFileSync(process.argv[2])).digest('hex');
if (digest !== '{{TOOLS_SHA256}}') throw new Error('Tools archive digest mismatch.');
console.log('Tools archive digest verified.');
NODE
  mkdir "$driver_kit/installed-tools"
  cd "$driver_kit/installed-tools"
  npm install --prefix "$driver_kit/installed-tools" --workspaces=false \
    --offline --ignore-scripts --no-audit --no-fund \
    "$driver_kit/tools/browser-driver-tools-{{VERSION}}.tgz"
  node node_modules/@browser-driver/release-tools/lib/consumer-cli.mjs \
    verify --bundle "$driver_kit/bundle" --sha256 '{{MANIFEST_SHA256}}'
)

What success looks like: “Tools archive digest verified.” followed by the bundle report for {{VERSION}} with trustedDigestProvided: true. Stop on any error. If installed-tools already exists, inspect that installation or start with a new extraction; do not overwrite it.

Only this portable-tools install is offline. The runtime, Rust dependencies and matching Chromium need their normal downloads. Your agent completes those steps while building your application’s separate integration.

3. Connect one flow with your agent

In Codex, open your application project and point the agent to AGENT_START.md inside the extracted daedlo-{{VERSION}} folder. Give it the actual path and one existing flow you want to verify.

A STARTING REQUEST / REPLACE THE KIT PATH
Read /absolute/path/to/daedlo-{{VERSION}}/AGENT_START.md. Verify the release and set up a separate QA integration in this project. Reuse our accepted behavior and help me choose one existing flow. Preserve our application, dependencies, data, and working tooling. Install the bundled skill, connect the Rust state model and JavaScript adapter, then run the flow in a visible viewer and show me its evidence. Verify a real outcome and, for a save, independently read back the persisted data. Verify a relevant negative case. Preserve the evidence, close owned resources, then relaunch and repeat the flow. Record the exact versions and any unverified steps.

The agent follows the kit’s installation instructions, checks dependencies, and helps connect your application. Explicitly read the bundled skill if automatic discovery is unavailable. The alpha requires an application-specific Rust model and JavaScript adapter; downloading the kit does not discover those for you.

4. See your own flow run

Your agent builds the integration’s model and adapter, installs the pinned runtime and Chromium, and leaves a project-specific launch command. Agree on the states, actions, and outcomes that matter. Launch the local viewer, follow the controlled browser, and inspect both the application outcome and the evidence behind it. The default controlled browser is headless Chromium streamed into the visible local viewer.

Authored checks run without an AI agent or model API key. Assisted setup uses your own Codex access. Customer application dependencies and any fixture services are separate from the kit.
