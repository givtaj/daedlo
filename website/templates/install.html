1. Download and verify

Save the ZIP and its SHA256SUMS file in the same new folder. Before extracting or running the kit, compare the archive’s SHA-256 with the value below. The checksum file covers the ZIP only.

EXPECTED ZIP SHA-256{{ZIP_SHA256}}

From that folder, check the checksum and then extract the archive: 

shasum -a 256 -c SHA256SUMS && \
  unzip daedlo-{{VERSION}}.zip

Continue only when the check reports OK. This checks download integrity against the published digest; it does not verify your application’s behavior. Use a local SHA-256 tool if your system does not provide shasum.

2. Verify and install the tools

In your terminal, enter the newly extracted folder:

cd daedlo-{{VERSION}}

Run this complete block. It is the same block verified from the kit’s START_HERE.md: check the tools archive before running it, install the portable tools, then verify the runtime and engine bundle.

macOS tools installation commands 
(
  set -eu
  driver_kit="$(pwd -P)"
  node --input-type=module - "$driver_kit/{{TOOLS_FILE}}" <<'NODE'
import { readFileSync } from 'node:fs';
import { createHash } from 'node:crypto';
const digest = createHash('sha256').update(readFileSync(process.argv[2])).digest('hex');
if (digest !== '{{TOOLS_SHA256}}') throw new Error('Tools archive digest mismatch.');
console.log('Tools archive digest verified.');
NODE
  mkdir "$driver_kit/installed-tools"
  cd "$driver_kit/installed-tools"
  npm install --prefix "$driver_kit/installed-tools" --workspaces=false \
    --offline --ignore-scripts --no-audit --no-fund \
    "$driver_kit/{{TOOLS_FILE}}"
  node node_modules/{{TOOLS_PACKAGE}}/lib/consumer-cli.mjs \
    verify --bundle "$driver_kit/bundle" --sha256 '{{MANIFEST_SHA256}}'
)

What success looks like: “Tools archive digest verified.” followed by the bundle report for {{VERSION}} with trustedDigestProvided: true. Stop on any error. If installed-tools already exists, inspect that installation or start with a new extraction; do not overwrite it.

Only this portable-tools install is offline. The runtime, Rust dependencies and matching Chromium need their normal downloads. Your agent completes those steps while building your application’s separate integration.

Keep context while your app restarts

Alpha.10 separates viewer, browser, application observation and live image status with labelled icons. If your API or site is rebuilding, unavailable observations disable actions while the last completed run keeps its result. A visible page does not establish API health; the adapter must observe the facts your flow requires.

Check connection is read-only. Fresh observations can make actions available again; reconnecting never replays an earlier command or reloads your application. Preserve drafts before any manual reload and reconcile an interrupted write before running it again.

Viewer closed confirms an explicit viewer close, which does not itself close an attached browser or application. Unexpected connection loss shows Reconnecting, then Connection lost. If the viewer restarts on another port, open its newly printed URL. Source changes do not replace an adapter already loaded in a session.

What changed in this alpha

  • Alpha.10 keeps run results separate from connection alerts and labels stale images. Swagger selection reveals supported collapsed or virtualized operations and gives clearer recovery guidance when an operation cannot be selected. Read-only request results explain that persistence was not attempted.
  • Alpha.9 introduced reusable Swagger UI driving for a bounded subset of OpenAPI 3.0, 3.1 and 3.2 JSON. Allowed requests run through the visible explorer; unsupported capabilities fail closed. A successful HTTP response does not prove business success or persistence.
  • Explicit password parameters are masked in the viewer and cleared after submission. Request values stay out of shared reports; Swagger itself can still display private requests and responses.
  • The application, active flow and results share the live workspace grid, with distinct evidence collection and cleanup states.
  • Alpha.7 distinguishes failed observation from stopped ownership, keeps unknown draft safety explicit and supports fresh guarded recovery without replaying a command. Existing installations need the separately verified native tools described in the update guide.
  • Alpha.4 uses Daedlo package names and verifies installed runtime dependencies before reporting that setup is ready.
  • Existing alpha.3 installations use an independently verified tools upgrade before moving to the renamed packages. Follow the managed-update instructions.
  • Ninja-Update verifies and tests new versions separately, then lets you restart or revert while preserving your authored integration and application data.
  • Cleared text stays empty when you submit a viewer command.
  • Pause and Stop remain effective while final evidence is collected.
  • Visible typing and cursor movement make guarded actions easier to follow.
  • CLI shutdown preserves the final report and retries failed owned cleanup.

Stopping cannot undo a request already sent. Execution, application outcome and persistence evidence remain separate.

Previous alpha.2 release checks on 21 October 2026. Source CI passed on Node.js 22 and 24 on Ubuntu. That exact alpha.2 kit passed macOS arm64 acceptance: eight browser/API groups, 10 CLI cases, 25 finalization cases and nine browser-control cases, including owned cleanup.

The Architecture Studio flow passed seven acceptance checkpoints, plus 13 Rust and seven Node tests. An empty required name was refused without a write. A save agreed across the response, independent API and disk reads, and the editor restored its fields after reload. CLI shutdown retained the report; relaunching the CLI and controlled browser repeated the save. Owned processes closed and ports were released. The application server was not restarted.

Read the dated verification record for the exact source, package, customer handoff and remaining limits. Ubuntu CI provides technical coverage; Linux customer onboarding remains unverified.

Public component licences, with their history intact.

From 0.1.4-alpha.4, Daedlo’s public core uses Apache-2.0. Required legacy MIT and third-party licence notices remain included. This change does not revoke permissions already granted for earlier releases.

The published 0.1.4-alpha.3 kit remains MIT AND Apache-2.0: Daedlo additions use MIT; Roots-derived portions retain Apache-2.0. Its downloads and included licence texts and notices are unchanged.

Your application, models, flows, adapters and data are separate from Daedlo’s public-core licence. Integrating Daedlo does not transfer ownership or require you to publish them. Third-party code you include keeps its own terms. Alpha.4 uses Daedlo package and skill names. Earlier downloads retain their original browser-driver names; follow the instructions bundled with the version you install.

Start small. Linux, Windows and Claude Code onboarding remain unverified. Fresh OS/toolchain installation, unfamiliar-framework coverage and independent self-service onboarding are outside this alpha. An installed kit begins your application’s acceptance work.
