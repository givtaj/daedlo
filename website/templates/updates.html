1. Set up managed updates once

Verify and install the alpha.3 tools in a separate directory. Alpha.2 cannot upgrade the manager itself. Read docs/ninja-update.md in the installed tools, then ask your agent:

Use our accepted Daedlo integration to register this project for Ninja-Update. Preserve the exact model, states, flows, adapter, configuration, dependency locks, instructions and custom skills. Add a reviewed managed launcher and acceptance checks using disposable data. Keep our application and its persistent data outside the update store. Verify the public publisher key below, then configure the signed preview feed. Show the first accepted flow and a relevant no-write failure before calling this project ready.

The agent supplies the real paths and model identity. This is an integration step: a signed download alone does not establish that your application still behaves correctly. Unsupported contracts or source changes need review.

2. Pin the publisher key

The feed is signed with Ed25519. The trusted key is {{KEY_ID}}, published by daedlo. Download the public key and compare its exact PEM file SHA-256 with this reviewed value before adding it to your local configuration. Also compare it with docs/update-trust/production.json and the bundled public PEM in your independently verified installed tools. The key and checksum on this page alone are not an independent trust source. Keep that pin; never replace it with a key suggested by an unverified feed.

This is only the catalog section. Your complete configuration also needs the reviewed registration, a separate managed store, and trusted launcher settings. It must not contain production credentials for disposable acceptance.

3. Install, validate, restart

From the installed tools directory, launch the local update screen using the actual configuration path prepared by your agent: 

node node_modules/@browser-driver/release-tools/lib/ninja.mjs serve \
  --config /absolute/path/to/ninja-local.json

Open the loopback URL printed by the command. It contains a private local token; keep it local. Choose Check for updates → Install update. The manager verifies the release, rebuilds the unchanged Rust model, installs isolated dependencies and runs registered checks. Ready means those checks passed.

Choose Restart Daedlo at a safe boundary. Active runs, paused runs and unsaved or unknown browser drafts block replacement. The manager saves the final report and closes its owned driver resources; attached application services stay running. Startup connects and observes without replaying your application flow.

Revert without overwriting your project

Revert update selects the previous verified installation, including its recorded adapter and source snapshot. Current authored files and application data remain unchanged. Business writes already made are not undone, and browser login state or unsaved drafts are not promised to survive a restart.

Keep the previous installation and accepted browser cache. The browser executable and observed version are checked again; a missing or changed executable blocks startup or rollback. Linked browser frameworks are not sealed by that executable hash. Failed or uncertain cleanup also blocks replacement and retains evidence for review.

A short-lived signed feed

This catalog expires at {{EXPIRES_AT}}. Catalog validity is at most seven days. GitHub Actions renews this catalog daily with an increasing generation and verifies the published result. Release downloads stay unchanged. If renewal fails, the publisher must resolve it before the displayed expiry; clients never bypass expiry checks.

An expired catalog blocks new update checks and downloads. It leaves the installed version running and existing local rollback available, subject to the same integrity and safe-restart checks. Do not bypass expiry or replace your pinned key to recover; contact support@daedlo.com.

Historical downloads remain available at their immutable version URLs, including alpha.2 metadata. The current release verification record separates package checks, real application acceptance and platform limits.
