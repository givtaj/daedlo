The tool inside the work

Born inside Roots.
Shaped by real
product work.

BUILT WHILEbuilding.ROOTS → DAEDLO

We were building Roots. And we needed a better way to see what we were building.

Real journeys raised concrete questions. Did a draft survive navigation? Had a save actually persisted? Could a failed request recover without creating a duplicate?

We built a driver inside Roots to make those journeys explicit: the state the application was in, the actions available, and the outcome each action produced. We could watch the browser, pause it, and inspect the evidence.

Then we extracted the reusable engine. Other builders could bring their own applications, their own flows, and their own definition of working.

WHY DAEDLO?

A coined name inspired by Daedalus, the craftsman of Greek legend. A nod to making the instrument your own work needs.

A focused first step

Start with one flow
that matters.

This alpha starts with one agreed existing flow and a relevant negative case. Your agent connects the application, preserves the evidence, then verifies shutdown and a repeat run.

For other browser flows, application-specific integration connects a Rust state model and a JavaScript adapter. Swagger reuses the shipped integration with your request policy. Your application keeps its own language and architecture.
