# 0.1.1-rc.2 — agent-installed QA developer preview

Release channel: GitHub pre-release `v0.1.1-rc.2`. The release page and attached
`VERIFICATION.md` record the final source, CI and downloadable-artifact identities.
The repository's existing visibility applies. This release does not publish to
npm or crates.io or change Roots' everyday driver.

## What this preview provides

An agent can install the native Rust engine library and Node/Playwright runtime,
help a team agree one feature's enum and transition diagram, connect its browser
flows, and leave inspectable results. The application keeps its existing language
and architecture. Authored commands and recipes run without an AI agent or model
API key once the customer integration exists.

- Portable `browser-driver` skill with installation, model/flow guidance and a
  story-to-state-to-evidence template for Codex and Claude Code projects.
- Shared typed Rust `ApplicationModel`, guarded Node execution and a local live
  viewer with command availability, speed, pause/resume/stop and separate execution,
  application-outcome and persistence reports.
- Versioned package bundles, exact-artifact verification, explicit store selection
  and rollback, and independent installed-package browser acceptance.
- Actual Roots workflow examples and sourced historical evidence, kept separate
  from the independent notebook conformance fixture and new candidate checks.
- Portable sibling-checkout defaults in the Roots reference helpers, with explicit
  source overrides preserved; private chat links removed from distributable docs.

The skill formalizes a workflow derived from actual Roots use: discover a useful
flow, agree its model, implement guarded actions, verify observable outcomes, and
record evidence another contributor can reuse. The customer still authors the
model, adapter, fixtures and assertions; this is not generic zero-configuration
onboarding or automatic test generation.

## Assets and installation

Use the [release installation guide](../releases.md) and
[agent onboarding guide](../agent-onboarding.md). Select the tag's source checkout
as well as the assets: the release CLI is not included in the package bundle.

| Asset | Purpose |
| --- | --- |
| `browser-driver-runtime-0.1.1-rc.2.tgz` | Exact `@browser-driver/runtime` package |
| `browser-driver-engine-0.1.1-rc.2.crate` | Shared Rust library source; build the customer's engine separately |
| `manifest.json` | Source identity, compatibility and artifact sizes/digests |
| `SHA256SUMS` | Canonical bundle checksum inventory, including the manifest |
| `browser-driver-agent-skill-0.1.1-rc.2.tar.gz` | Complete `browser-driver/` skill folder: `SKILL.md`, `LICENSE`, `references/`, `assets/` |
| `AGENT_SKILL_SHA256SUMS` | Separate skill archive checksum inventory |
| `VERIFICATION.md` | Final source, CI, package acceptance and artifact receipt |

The first four files are the canonical bundle. The skill is a separate asset and
also appears in the tag's source archive under `skills/browser-driver/`. Pin the
source commit and verify the bundle and skill against the selected trusted release
receipt before installing them.

Requirements: Node 22+, Rust/Cargo 1.96.0+ (repository toolchain 1.96.0), and the
runtime's Playwright 1.62.1 Chromium. Docker is required only by fixtures that use
it. Application-specific prerequisites may add requirements.

## Verification receipt

Publication requires the existing Ubuntu Node 22/24 CI checks on the exact tagged
commit, an installed-package Chromium run against the selected bundle, and skill
archive content/checksum verification. CI is unchanged; publication is an explicit
maintainer operation after those checks.

Use the [GitHub release receipt](https://github.com/givtaj/browser-driver/releases/tag/v0.1.1-rc.2)
for the final commit, CI run, manifest/skill digests and downloadable assets. The
attached `VERIFICATION.md` is generated after the source commit and clean bundle
exist. Earlier local and customer results retain their original scope in
[verification](../verification.md); they are not relabeled as new customer tests.

## Known limits

The viewer is local. Customers must supply a model, browser adapter and readiness,
authentication and cleanup rules. A compatible protocol or successful package
installation does not prove a customer's business flow.

Windows, complete onboarding of an unfamiliar application, and full Claude Code
skill discovery and end-to-end onboarding have not been tested. The portable skill
is an instruction distribution, not an installed agent plugin or MCP server.
Roots' current embedded driver, normal dependencies, services and data remain
unchanged; selected isolated Roots acceptance is not an all-recipe migration.
