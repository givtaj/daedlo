# Getting help with Daedlo

Start with the [README](README.md), [source setup](CONTRIBUTING.md),
[application onboarding guide](docs/agent-onboarding.md) or the instructions inside
your exact downloaded kit. The [verification record](docs/verification.md)
distinguishes released capabilities from unverified work.

For reproducible bugs and concrete feature proposals, use the repository's
[issue tracker](https://github.com/givtaj/daedlo/issues). While repository access
is private, this tracker is available only to people with access. Questions about
installation or access can go to [support@daedlo.com](mailto:support@daedlo.com).
There is no guaranteed support response time.

Include your OS/architecture, Daedlo version or commit, Node and Rust versions,
exact command, expected result and a small sanitized reproduction. Say whether the
failure happened during setup, a source check, a browser flow or installed-package
acceptance. Do not attach full private traces, cookies, account credentials,
customer records or local update-screen URLs.

Report vulnerabilities through [SECURITY.md](SECURITY.md), and conduct concerns
through [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
